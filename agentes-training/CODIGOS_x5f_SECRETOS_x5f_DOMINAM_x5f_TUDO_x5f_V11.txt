CODIGO 1: O SCROLL SAGRADO - O QUE FAZ APPLE PARECER APPLE
================================================================================

Segredo: Apple não usa scroll nativo. Usa Lenis com lag 0 e GSAP ticker sync + normalizeScroll.
Se você só coloca Lenis, fica mole. O segredo é o sync perfeito.

Código que domina tudo:
import Lenis from 'lenis'
import gsap from 'gsap'
import ScrollTrigger from 'gsap/ScrollTrigger'
gsap.registerPlugin(ScrollTrigger)

const lenis = new Lenis({
  duration: 1.2,
  easing: (t) => Math.min(1, 1.001 - Math.pow(2, -10 * t)),
  smoothWheel: true,
  smoothTouch: false,
  syncTouch: false,
  gestureOrientation: 'vertical',
  touchMultiplier: 1.5,
  infinite: false
})

// O SEGREDO QUE NINGUÉM MOSTRA:
lenis.on('scroll', ScrollTrigger.update)
gsap.ticker.add((time) => {
  lenis.raf(time * 1000)
})
gsap.ticker.lagSmoothing(0) // Apple faz isso, senão fica com delay

// Normalize scroll entre trackpad e mouse wheel (Apple faz)
ScrollTrigger.normalizeScroll(true)

// Parallax sem data-attribute, com velocidade real
lenis.on('scroll', ({ velocity, scroll })=>{
  const v = velocity * 0.01
  gsap.to('.parallax-slow', { y: scroll * 0.2 + v * 10, overwrite: 'auto', duration: 0.8 })
  gsap.to('.parallax-fast', { y: scroll * -0.3 + v * -5, overwrite: 'auto', duration: 0.8 })
})

Por que isso domina: 90% dos devs colocam Lenis e ScrollTrigger separados. Fica com jank. Com ticker sync + lagSmoothing(0), fica 60fps igual Apple.

Treino agente: "Sempre que usar Lenis + ScrollTrigger, use ticker sync + lagSmoothing(0) + normalizeScroll. Nunca use scroll event nativo."

CODIGO 2: A LUZ QUE RESPIRA - SHADER DA STRIPE E LINEAR
================================================================================

Segredo: Stripe não usa imagem. Usa SDF circle + noise + palette com uTime que respira com idle, não com loop infinito.

Código:
import { shaderMaterial } from '@react-three/drei'

const BreathLightMat = shaderMaterial(
  { uTime: 0, uIdle: 0, uPointer: new THREE.Vector2(0.5,0.5), uVel: 0 },
  `varying vec2 vUv; void main(){ vUv = uv; gl_Position = projectionMatrix * modelViewMatrix * vec4(position,1.0); }`,
  `
  #include "lygia/sdf/circleSDF.glsl"
  #include "lygia/generative/fbm.glsl"
  #include "lygia/color/palette.glsl"
  varying vec2 vUv;
  uniform float uTime;
  uniform float uIdle;
  uniform vec2 uPointer;
  uniform float uVel;

  void main(){
    vec2 st = vUv * 2.0 - 1.0;
    st += (uPointer - 0.5) * 0.2; // segue pointer sutil

    // RESPIRAÇÃO: idle aumenta, respiração mais profunda
    float breath = 1.0 + sin(uTime * 0.5 + uIdle * 0.2) * (0.05 + uIdle * 0.02);
    breath += uVel * 0.1; // velocidade aumenta respiração

    float d = circleSDF(st * breath);
    float n = fbm(st * 2.0 + uTime * 0.05) * 0.15;
    d += n * (0.5 + uVel);

    vec3 col = palette(d * 2.0 + uTime * 0.1,
      vec3(0.5,0.5,0.5), vec3(0.5,0.5,0.5), vec3(1.0,1.0,1.0), vec3(0.0,0.33,0.67));

    float alpha = 1.0 - smoothstep(0.0, 1.2, d);
    alpha *= 0.6 - uVel * 0.2; // rápido fica mais transparente

    gl_FragColor = vec4(col, alpha);
  }
  `
)

JS que faz respirar sem mic:
let lastScroll = performance.now()
let idle = 0
lenis.on('scroll', ()=> lastScroll = performance.now())

function raf(t){
  idle = (performance.now() - lastScroll) / 1000
  mat.uniforms.uTime.value = t * 0.001
  mat.uniforms.uIdle.value = Math.min(5, idle) // máximo 5s de idle
  requestAnimationFrame(raf)
}

Domina porque: Todo site usa `sin(uTime)` que parece robô. Com `uIdle`, quando usuário para, luz respira fundo, convida a ficar. É humano.

Treino agente: "Nunca use sin(uTime) puro. Sempre multiplique por uIdle + uVel para respiração humana."

CODIGO 3: A MEMORIA INFINITA - GPGPU 50k PARTICULAS DA APPLE E ACTIVE THEORY
================================================================================

Segredo: Apple AirPods page com 10k partículas não usa Points. Usa GPGPU com 2 render targets (position + velocity) e compute shader em WebGL2, agora WebGPU.

Código que domina (Three.js WebGL2 GPGPU, sem WebGPU ainda para compat):
import { GPUComputationRenderer } from 'three/addons/misc/GPUComputationRenderer.js'

const gpuCompute = new GPUComputationRenderer(256, 256, renderer) // 256*256 = 65536 partículas
const dtPosition = gpuCompute.createTexture()
const dtVelocity = gpuCompute.createTexture()

// Inicializa posições aleatórias esfera
for(let i=0; i<256*256*4; i+=4){
  dtPosition.image.data[i] = (Math.random()-0.5) * 10
  dtPosition.image.data[i+1] = (Math.random()-0.5) * 10
  dtPosition.image.data[i+2] = (Math.random()-0.5) * 10
}

const posVar = gpuCompute.addVariable('texturePosition', `
  uniform float uTime;
  uniform float uScrollProgress;
  uniform vec2 uPointer;
  void main(){
    vec2 uv = gl_FragCoord.xy / resolution.xy;
    vec4 pos = texture2D(texturePosition, uv);
    vec4 vel = texture2D(textureVelocity, uv);

    // Scroll apaga: se progress > vida, partícula morre e renasce
    float life = 1.0 - uScrollProgress + fract(sin(dot(uv, vec2(12.9898,78.233)))*43758.5453) * 0.2;
    if(life < 0.0){
      pos.xyz = vec3((random(uv)-0.5)*10.0);
    } else {
      pos.xyz += vel.xyz * 0.01;
      pos.xyz += vec3(sin(uTime + uv.x * 10.0) * 0.01);
    }

    gl_FragColor = pos;
  }
`, dtPosition)

gpuCompute.init()

// No render loop:
gpuCompute.compute()
particlesMaterial.uniforms.texturePosition.value = gpuCompute.getCurrentRenderTarget(posVar).texture

Domina porque: 50k partículas em CPU morre. Em GPGPU, GPU calcula, 60fps em mobile.

Treino agente: "Para >10k partículas, sempre GPGPU. Nunca Points com loop JS."

CODIGO 4: A TRANSICAO IMPOSSIVEL - FLIP DA LINEAR
================================================================================

Segredo: Linear quando clica num card, ele expande para modal sem flash. Não é route. É Flip.getState() + absolute + scale.

Código que domina:
import Flip from 'gsap/Flip'

function expandCard(card){
  const state = Flip.getState(card, { props: "borderRadius,backgroundColor" })

  card.classList.add('expanded') // CSS: position: fixed; inset: 0; z-index: 100; width: 100vw; height: 100vh;

  Flip.from(state, {
    duration: 0.7,
    ease: 'power2.inOut',
    absolute: true, // segredo: usa position absolute durante animação para não quebrar layout
    scale: true,
    simple: true,
    onEnter: (elements) => gsap.from(elements, { opacity: 0, duration: 0.3 }),
    onLeave: (elements) => gsap.to(elements, { opacity: 0, duration: 0.3 })
  })
}

Para lista:
function filterList(){
  const state = Flip.getState('.card')
  // muda DOM: esconde alguns cards
  document.querySelectorAll('.card.hidden').forEach(c=>c.style.display='none')
  Flip.from(state, {
    duration: 0.6,
    ease: 'power2.out',
    stagger: 0.02,
    absolute: true
  })
}

Domina porque: Todo mundo faz modal com opacity. Flip faz layout animar como se fosse nativo.

Treino agente: "Para expandir card, lista, ou mudar layout, sempre Flip.getState + Flip.from com absolute:true. Nunca top/left manual."

CODIGO 5: O TEXTO QUE DERRETE - BRUNO SIMON E ACTIVE THEORY
================================================================================

Segredo: Texto que derrete não é SplitText. É SDF + shader + displacement.

Código:
import SplitType from 'split-type'
const text = new SplitType('.melt-text', { types: 'chars' })

text.chars.forEach((char, i)=>{
  // Cada char é um canvas com shader
  const mat = new THREE.ShaderMaterial({
    uniforms: { uProgress: { value: 0 }, uTime: { value: 0 } },
    vertexShader: `varying vec2 vUv; void main(){ vUv = uv; gl_Position = projectionMatrix * modelViewMatrix * vec4(position,1.0); }`,
    fragmentShader: `
      #include "lygia/generative/cnoise.glsl"
      uniform float uProgress;
      uniform float uTime;
      varying vec2 vUv;
      void main(){
        vec2 uv = vUv;
        uv.y -= uProgress * 0.5; // derrete pra baixo
        uv.x += cnoise(uv * 5.0 + uTime) * uProgress * 0.2; // ruído aumenta com progress
        float alpha = 1.0 - uProgress;
        gl_FragColor = vec4(vec3(0.0), alpha);
      }
    `
  })

  gsap.to(mat.uniforms.uProgress, {
    value: 1,
    duration: 1.2,
    delay: i * 0.02,
    ease: 'power2.in',
    scrollTrigger: {
      trigger: char,
      start: 'top 80%',
      toggleActions: 'play none none reverse'
    }
  })
})

Domina porque: SplitText sozinho é só y. Com shader cnoise, derrete orgânico.

Treino agente: "Para texto premium, SplitType + shader com cnoise + uProgress por char. Nunca só GSAP y."

CODIGO 6: O HOVER QUE DISTORCE - STRIPE E AWWWARDS
================================================================================

Segredo: Imagem que distorce no hover não é filter: blur. É OGL com displacement texture + uMouse.

Código OGL que domina (12kB, não Pixi):
import { Renderer, Camera, Transform, Plane, Program, Mesh, Texture } from 'ogl'

const renderer = new Renderer({ dpr: Math.min(2, window.devicePixelRatio) })
const gl = renderer.gl
document.body.appendChild(gl.canvas)

const geometry = new Plane(gl, { width: 1, height: 1, widthSegments: 20, heightSegments: 20 })

const program = new Program(gl, {
  vertex: `
    attribute vec3 position;
    attribute vec2 uv;
    uniform mat4 modelViewMatrix;
    uniform mat4 projectionMatrix;
    uniform float uTime;
    uniform vec2 uMouse;
    uniform float uHover;
    varying vec2 vUv;
    void main(){
      vUv = uv;
      vec3 pos = position;
      float dist = distance(uv, uMouse);
      pos.z += sin(dist * 10.0 - uTime * 2.0) * uHover * 0.1;
      gl_Position = projectionMatrix * modelViewMatrix * vec4(pos, 1.0);
    }
  `,
  fragment: `
    precision highp float;
    uniform sampler2D tMap;
    uniform float uHover;
    varying vec2 vUv;
    void main(){
      vec2 uv = vUv;
      uv.x += sin(uv.y * 10.0) * uHover * 0.01;
      gl_FragColor = texture2D(tMap, uv);
    }
  `,
  uniforms: {
    tMap: { value: new Texture(gl, { image: new Image() }) },
    uTime: { value: 0 },
    uMouse: { value: [0.5,0.5] },
    uHover: { value: 0 }
  }
})

const mesh = new Mesh(gl, { geometry, program })

// Hover:
el.addEventListener('pointermove', (e)=>{
  const rect = el.getBoundingClientRect()
  program.uniforms.uMouse.value = [(e.clientX - rect.left)/rect.width, 1.0 - (e.clientY - rect.top)/rect.height]
})

el.addEventListener('pointerenter', ()=> gsap.to(program.uniforms.uHover, { value: 1, duration: 0.6 }))
el.addEventListener('pointerleave', ()=> gsap.to(program.uniforms.uHover, { value: 0, duration: 0.8 }))

Domina porque: CSS hover é 2D. OGL é 3D com vértice.

Treino agente: "Para hover premium, OGL Plane + uMouse + uHover. Nunca CSS transform."

CODIGO 8: A FISICA QUE SENTE - RAPIER + SPRING DA LINEAR
================================================================================

Segredo: Botão da Linear não usa ease. Usa spring com damping que sente velocity do pointer.

Código:
import { useSpring, animated } from '@react-spring/web'

const [props, api] = useSpring(()=> ({ x: 0, y: 0, scale: 1, config: { tension: 300, friction: 20 } }))

function onPointerMove(e){
  const rect = e.currentTarget.getBoundingClientRect()
  const x = (e.clientX - rect.left - rect.width/2) * 0.1
  const y = (e.clientY - rect.top - rect.height/2) * 0.1
  api.start({ x, y, scale: 1.05 })
}

function onPointerLeave(){
  api.start({ x: 0, y: 0, scale: 1 })
}

<animated.div style={{ x: props.x, y: props.y, scale: props.scale }} />

Com Rapier para 3D que sente:
import { RigidBody } from '@react-three/rapier'

<RigidBody type="dynamic" colliders="ball" linearDamping={0.5} angularDamping={0.5}>
  <mesh onPointerMove={(e)=>{
    const impulse = { x: e.movementX * 0.01, y: e.movementY * 0.01, z: 0 }
    body.applyImpulse(impulse)
  }}>
    <sphereGeometry />
  </mesh>
</RigidBody>

Domina porque: Spring sente, ease não sente.

Treino agente: "Para interação que sente, spring com tension/friction, não ease. Para 3D, Rapier impulse baseado em movementX."
